# 各种模型的部署方式

> 本文档梳理天枢用到的全部模型，及其下载、存储、服务化（vLLM）与运行时加载方式。涉及 [download_models.py](../backend/download_models.py)、[docker-compose.yml](../docker-compose.yml)、[docker-compose.cpu.yml](../docker-compose.cpu.yml)、各 Dockerfile 与 [scripts/](../scripts/)。

## 0. 模型清单总览

| 模型 | 用途 | 来源 | 部署方式 |
|------|------|------|----------|
| **PDF-Extract-Kit-1.0** | MinerU pipeline 版面/公式/表格 | ModelScope | 预下载到 `./models` |
| **MinerU2.5-Pro-2605-1.2B** | MinerU VLM | ModelScope | 预下载 + vLLM 服务化 |
| **PaddleOCR-VL-1.6-0.9B** | 多语种 OCR | HuggingFace | 预下载 + 本地/vLLM |
| **SenseVoiceSmall** | 音频 ASR | ModelScope | 预下载到 `./models` |
| **Paraformer-large**（可选）| 说话人分离 | ModelScope | 预下载 |
| **YOLO11x watermark**（可选）| 去水印检测 | HuggingFace | 预下载 `best.pt` |
| **LaMa / PP-OCRv5 / PP-DocLayout 等** | OCR/版面/修复子模型 | PaddleX/Paddle | 运行时自动下载 |

两类下载策略：**重模型预下载**（MinerU、VLM、SenseVoice、YOLO），**轻量 PaddleX/PaddleOCR 子模型运行时自动下载**到挂载的缓存目录。

## 1. 模型下载脚本 `download_models.py`

[download_models.py](../backend/download_models.py)：把关键模型预下载到 `./models`（`--output` 指定，默认 `./models`）。

**预下载模型**（`MODELS` 字典，[download_models.py:31](../backend/download_models.py#L31)）：

| key | model_id | source | 目标目录 |
|-----|----------|--------|----------|
| `mineru_pipeline` | `OpenDataLab/PDF-Extract-Kit-1.0` | modelscope | `PDF-Extract-Kit-1.0` |
| `mineru_vlm` | `OpenDataLab/MinerU2.5-Pro-2605-1.2B` | modelscope | `MinerU2.5-Pro-2605-1.2B` |
| `paddleocr_vl_1_6` | `PaddlePaddle/PaddleOCR-VL-1.6` | huggingface | `paddlex_cache/official_models/PaddleOCR-VL-1.6-0.9B` |
| `sensevoice` | `iic/SenseVoiceSmall` | modelscope | `SenseVoiceSmall` |
| `paraformer`（可选）| `iic/speech_seaco_paraformer...` | modelscope | `Paraformer` |
| `yolo11`（可选）| `corzent/yolo11x_watermark_detection`（`best.pt`）| huggingface | `YOLO11` |

**运行时自动下载**（`auto_download:True`，脚本跳过）：PP-DocLayoutV3/V2、PP-OCRv5 det/rec、PP-FormulaNet、SLANet 表格、LaMa 修复等，落到 `./models/paddlex_cache`（挂载到 `/root/.paddlex`）与 `./models/paddleocr_cache`（`/root/.paddleocr`）。

**CLI**：`--output`（输出目录）、`--models`（逗号过滤）、`--force`（强制重下）。容器中调用 `python download_models.py --output /app/models`。

**下载机制**：HuggingFace 用 `snapshot_download`（`resume_download=True`，镜像 `HF_ENDPOINT=https://hf-mirror.com`）；ModelScope 用 `snapshot_download(revision="master")`。`verify_model_files` 校验关键子路径（如 MinerU 的 `Layout/MFR/OCR`、VLM 的 `.safetensors`、YOLO 的 `.pt`）。可选模型失败忽略，必需模型失败 → 退出码 1。最后写 `manifest.json`。

### `mineru.json`（MinerU 3.0 配置）

由 `generate_mineru_json`（[download_models.py:283](../backend/download_models.py#L283)）写到 `<output>/mineru.json`，**嵌套格式 + `config_version` 1.3.1**：

```json
{
    "models-dir": {
        "pipeline": "/app/models/PDF-Extract-Kit-1.0/models",
        "vlm": "/app/models/MinerU2.5-Pro-2605-1.2B"
    },
    "config_version": "1.3.1"
}
```

`docker-entrypoint.sh` 把 `/app/models/mineru.json` 拷到 `~/mineru.json`（路径由 `MINERU_TOOLS_CONFIG_JSON` 控制）。

### 关键环境变量

| 变量 | 取值 | 说明 |
|------|------|------|
| `MODEL_DOWNLOAD_SOURCE` | `auto`/`modelscope`/`huggingface`/`local` | **被 MinerU/Paddle 运行时引擎消费**，非 `download_models.py`（脚本里 source 是按模型硬编码的）。`local` = 用已存在的本地模型 |
| `HF_OFFLINE` | `1` | CPU/离线栈强制 HuggingFace 库走本地缓存不联网 |
| `HF_ENDPOINT` | `https://hf-mirror.com` | HF 镜像 |
| `MODEL_PATH` | `/app/models` | 容器内模型根目录 |

> 运行时引擎选源逻辑见 [litserve_worker.py:268](../backend/litserve_worker.py#L268)：`modelscope`/`auto` 优先用 ModelScope，否则 HuggingFace 镜像。

## 2. GPU 生产部署（`docker-compose.yml`）

项目名 `tianshu`，网络 `tianshu-network`（172.28.0.0/16）。服务：

| 服务 | 镜像 | 容器 | 端口 | 说明 |
|------|------|------|------|------|
| `redis` | `redis:7-alpine` | tianshu-redis | 6379 | profile `redis`（按需）|
| `minio` | `minio/minio:latest` | tianshu-minio | 9000/9001 | 图片对象存储，桶 `ts-img` |
| `init-models` | `tianshu-backend:latest` | tianshu-init-models | — | 跑 `download_models.py`，其余服务等其完成 |
| `backend` | `backend/Dockerfile` | tianshu-backend | 8000 | API，预留 1 GPU |
| `scheduler` | `tianshu-backend:latest` | tianshu-scheduler | — | `task_scheduler.py --interval 60` |
| `vllm-paddleocr` | `vllm/vllm-openai:nightly` | **tianshu-vllm-paddleocr** | 30023 | 默认常驻 |
| `vllm-mineru` | `vllm/vllm-openai:nightly` | **tianshu-vllm-mineru** | 30024 | `profile: manual`，按需冷启 |
| `worker` | `tianshu-backend:latest` | tianshu-worker | 8001 | GPU 解析，挂 docker.sock |
| `mcp-server` | `tianshu-backend:latest` | tianshu-mcp | 8002 | MCP 协议 |
| `frontend` | `frontend/Dockerfile` | tianshu-frontend | 80 | Vue + Nginx |

### vLLM 服务化

**`vllm-paddleocr`（:30023，常驻）**——服务 `PaddleOCR-VL-1.6-0.9B`：
```
--model /root/.paddlex/official_models/PaddleOCR-VL-1.6-0.9B
--served-model-name PaddleOCR-VL-1.6-0.9B --trust-remote-code
--port 30023 --gpu-memory-utilization 0.6 --max-model-len 8192 --enforce-eager
```
挂载 `./models:/models:ro` 与 `./models/paddlex_cache:/root/.paddlex:ro`，`shm_size: 32gb`，`CUDA_VISIBLE_DEVICES=${VLLM_PADDLE_DEVICE:-0}`。

**`vllm-mineru`（:30024，按需）**——服务 `MinerU2.5-Pro-2605-1.2B`（served name `MinerU-1.2B`）：
```
--model /models/MinerU2.5-Pro-2605-1.2B --served-model-name MinerU-1.2B
--port 30024 --gpu-memory-utilization 0.6 --max-model-len 8192 --enforce-eager
```
`profile: manual` + `restart: no`，不随 `up` 自动起，由 Worker 按需冷启。

### Worker 如何连接 vLLM

```
python litserve_worker.py
  --paddleocr-vl-vllm-engine-enabled
  --paddleocr-vl-vllm-api-list ['http://vllm-paddleocr:30023/v1']
  --mineru-vllm-api-list ['http://vllm-mineru:30024/v1']
```
通过 `tianshu-network` 内部 DNS 主机名访问。每个 Worker 按 `global_index % len(list)` 分配 API 端点（[litserve_worker.py:249](../backend/litserve_worker.py#L249)）。Worker 强制串行：`MAX_CONCURRENT_TASKS=1`、`WORKER_GPUS=1`。

### vLLM 容器互斥切换

两个 vLLM 各占 `gpu-memory-utilization 0.6` 同一张卡（默认 device 0），不能同时驻留显存。[`VLLMController`](../backend/litserve_worker.py#L141) 通过挂载的 docker.sock 用 Docker SDK 切换：

```python
ensure_service(target_container, conflict_container):
    # 1. 冲突容器 running → stop()，sleep 2s 释放显存
    # 2. 目标容器未运行 → start()，轮询 30s 等 running
```

`_process_task` 分派（[litserve_worker.py:394](../backend/litserve_worker.py#L394)）：
- `backend == "paddleocr-vl-vllm"` → 起 paddle 停 mineru；
- `backend in ["vlm-auto-engine","hybrid-auto-engine"]` → 起 mineru 停 paddle。

Paddle 为默认常驻服务，MinerU 服务按需冷启（启动前先停 Paddle 腾显存）。

## 3. Mac/CPU 部署（`docker-compose.cpu.yml`）

项目名 `tianshu-cpu`（172.29.0.0/16）。与 GPU 栈的差异：

- **存储用 RustFS 替代 MinIO**：`rustfs/rustfs:latest`（容器 tianshu-rustfs-cpu，9000/9001，桶 `ts-img`），全部用 `RUSTFS_*` 环境变量，`RUSTFS_PUBLIC_URL` 走 `host.docker.internal`。
- **纯 CPU**：镜像 `tianshu-backend-cpu:latest`（`Dockerfile.cpu`），`platform: linux/amd64`（Apple Silicon 走 Rosetta），`ACCELERATOR=cpu`、`CUDA_VISIBLE_DEVICES=`空、`GPU_COUNT=0`，去掉所有 GPU `deploy.resources`。
- **无 vLLM、无 init-models、无 scheduler、无 mcp**，仅 `rustfs`/`backend`/`worker`/`frontend`。
- **离线模型**：`MODEL_DOWNLOAD_SOURCE=local`、`HF_OFFLINE=1`，额外挂载 `./models-offline:/models-external:ro` 及 HF/ModelScope 缓存。
- Worker 命令 `--accelerator cpu`，无 vLLM 参数；有 healthcheck。

> `docker-compose.offline.yml`：存储同 CPU 栈（RustFS、local、HF_OFFLINE），但用 GPU 镜像 `tianshu-backend:latest` 并含 redis，无 vLLM 容器。

## 5. 部署脚本与 Makefile

**`Makefile`**（GPU 栈）：`make setup`（复制 .env + 构建 + 启动）、`make start`/`stop`/`logs`，对应 `docker compose up -d` 等。

**`scripts/`**：
- `build-local-cpu.sh`：`docker buildx --platform linux/amd64` 构建 `tianshu-backend-cpu:latest`（`Dockerfile.cpu`）与前端镜像，校验 Docker、提示 Rosetta 与 `./models-offline`。
- `start-local-cpu.sh`：自动生成 `.env.cpu`（openssl 随机 JWT，强制 `ACCELERATOR=cpu`/`local`/`HF_OFFLINE=1`），`docker-compose -f docker-compose.cpu.yml --env-file .env.cpu up -d`，健康检查后打印 URL 与默认登录 `admin/admin123`。
- 其它：`docker-entrypoint.sh`、`init-models.sh`、`build-offline.sh`、`deploy-offline.sh`、`docker-setup.sh/.bat`。

## 6. 本地原生运行（无 Docker，Mac 常见开发路径）

```bash
cd backend && python start_all.py    # 需要 backend/.env
#   --accelerator cpu|cuda  --devices 0,1  --workers-per-device N
#   --output-dir <abs>  --enable-mcp --mcp-port 8002
```

- 原生 CPU 模式下**没有 vLLM 容器**，MinerU 走 pipeline CPU 引擎（慢），PaddleOCR-VL/VLM 不可用。
- 模型：`python backend/download_models.py --output ./models`（约 15GB，同时生成 `models/mineru.json`）。
- 注意容器路径（`/app/...`）在原生运行会因 `/app` 只读崩溃，须用绝对主机路径或留空回退到 `<repo>/data/...`。
