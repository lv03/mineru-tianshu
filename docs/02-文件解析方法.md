# 各种文件的解析方法

> 本文档梳理天枢支持的所有文件类型及其解析引擎、所用模型、关键选项与输出格式。引擎路由入口在 [litserve_worker.py `_process_task()`](../backend/litserve_worker.py#L384)，所有引擎最终统一归一化为 `result.md` + `result.json` + `images/`。

## 0. 引擎与文件类型总览

| 引擎 (`backend`) | 适用文件 | 所用模型/库 | GPU 要求 | 引擎文件 |
|------------------|----------|-------------|----------|----------|
| `pipeline` / `auto` | PDF、图片、DOCX | MinerU 3.0 内置版面/OCR/公式/表格模型 | 可 CPU（慢） | [mineru_pipeline/engine.py](../backend/mineru_pipeline/engine.py) |
| `vlm-*` / `hybrid-*` | PDF、图片、DOCX | MinerU 2.5 Pro VLM（1.2B，经 vLLM） | GPU | 同上 |
| `paddleocr-vl` | PDF、图片 | PaddleOCR-VL-1.6-0.9B（本地 CUDA；Mac/CPU 自动路由到 MLX） | NVIDIA GPU；Apple Silicon 可走 MLX | [paddleocr_vl/engine.py](../backend/paddleocr_vl/engine.py) |
| `paddleocr-vl-vllm` | PDF、图片 | PaddleOCR-VL-1.6-0.9B（经 vLLM） | GPU | [paddleocr_vl_vllm/engine.py](../backend/paddleocr_vl_vllm/engine.py) |
| `paddleocr-vl-mlx` | PDF、图片 | PaddleOCR-VL-1.6-0.9B（经 mlx-vlm server） | Apple Silicon（主进程 CPU + MLX/ANE VLM） | [paddleocr_vl_mlx/engine.py](../backend/paddleocr_vl_mlx/engine.py) |
| `sensevoice` | 音频 wav/mp3/flac/m4a… | SenseVoiceSmall / Paraformer | 可 CPU | [audio_engines/sensevoice_engine.py](../backend/audio_engines/sensevoice_engine.py) |
| `video` | mp4/avi/mkv/mov… | SenseVoice + PaddleOCR-VL 关键帧 | 可 CPU | [video_engines/video_engine.py](../backend/video_engines/video_engine.py) |
| MarkItDown（兜底）| Office/HTML/其它 | MarkItDown | CPU | （worker 内置） |
| 格式引擎 | FASTA/GenBank | BioPython | CPU | [format_engines/](../backend/format_engines/) |

`auto` 模式按扩展名自动挑选引擎，并对旧 Office 格式做转换兜底（见第 8 节）。

## 1. MinerU 引擎（PDF / 图片 / DOCX）

类 [`MinerUPipelineEngine`](../backend/mineru_pipeline/engine.py#L37)（单例），`parse()` 在 [engine.py:218](../backend/mineru_pipeline/engine.py#L218)，底层调用 MinerU 3.0 的 `do_parse`。

**输入处理**：
- `.pdf` 直接解析；
- `.png/.jpg/.jpeg` 先用 `img2pdf` 转 PDF；
- `.docx` 走 MinerU 原生 DOCX 解析（`office_docx_analyze`）。

**`parse_mode`（即 `backend`）取值**（[engine.py:243](../backend/mineru_pipeline/engine.py#L243)）：

| 模式 | 说明 |
|------|------|
| `pipeline` | 纯本地流水线：版面分析 + OCR + 公式 + 表格，CPU/GPU 均可 |
| `auto` | 等价于 `pipeline` |
| `vlm-auto-engine` | 配置了 `vlm_api_base` 时自动改写为 `vlm-http-client` |
| `hybrid-auto-engine` | 同上，改写为 `hybrid-http-client`（流水线 + VLM 混合）|
| `vlm-http-client` / `hybrid-http-client` | 直连 vLLM，启动前 `_wait_for_server` 轮询 `{base}/v1/models` 健康检查 |

> Pipeline 与 VLM 的选择**完全由 `parse_mode` 决定**。`vlm-*`/`hybrid-*` 仅在配置了本地 vLLM 服务（`--mineru-vllm-api-list`）时才会真正走 VLM；`server_url = vlm_api_base.replace("/v1","")`。

**关键选项**（[engine.py:266](../backend/mineru_pipeline/engine.py#L266)）：

| 选项 | 默认 | 说明 |
|------|------|------|
| `method` / `force_ocr` | `auto` | `parse_method`：`auto`/`ocr` |
| `lang` | `auto`（实为 `ch`）| OCR 语言 |
| `formula_enable` | `True` | 公式识别 |
| `table_enable` | `True` | 表格识别 |
| `start_page` / `end_page` | — | 页码范围 |
| `draw_layout_bbox` / `draw_span_bbox` | `True` | 生成 `_layout.pdf` / `_span.pdf` 可视化 |
| `dump_markdown` / `dump_middle_json` / `dump_content_list` | `True` | 输出控制 |

**输出**：在临时英文目录处理后，经 `_clean_markdown`（双重 HTML 反转义、去 `\mathrm{}`、去重、合并空行）清洗，返回 `{markdown, result_path, markdown_file, json_path, json_content}`。优先取 `*_content_list_v2.json`，回退 `*_content_list.json`。

**资源管理**：空闲 5 分钟自动休眠释放显存，新任务到来自动唤醒（[engine.py:89](../backend/mineru_pipeline/engine.py#L89)）。

## 2. PaddleOCR-VL 引擎（本地 CUDA / Apple Silicon MLX）

类 [`PaddleOCRVLEngine`](../backend/paddleocr_vl/engine.py#L44)（单例），`parse()` 在 [engine.py:204](../backend/paddleocr_vl/engine.py#L204)。

- **模型**：`PaddleOCR-VL-1.6-0.9B`，经 PaddleX v3 `create_pipeline` 加载。CUDA 本地模式需要 NVIDIA GPU（算力 ≥ 8.5）；Apple Silicon 原生开发时，Worker 在 `accelerator=cpu` 且可导入 `paddleocr_vl_mlx` 时，会把 `backend=paddleocr-vl` 自动路由到 MLX server。
- **输入**：PDF（原生多页）、图片（`.jpg/.png/.jpeg/.bmp`）。**支持 109+ 语种自动识别，无需指定 `lang`**。
- **关键选项**（camelCase API → snake_case，[engine.py:229](../backend/paddleocr_vl/engine.py#L229)）：
  `useLayoutDetection`（默认 True）、`useSealRecognition`（默认 True）、`useDocOrientationClassify`、`useDocUnwarping`、`useChartRecognition`、`useOcrForImageBlock`、`layoutNms`、`mergeTables`、`relevelTitles`、`restructurePages`、`markdownIgnoreLabels`、`minPixels`/`maxPixels`。
- **输出**：流式逐页保存 `page_N/`（图+JSON），合成 `result.md`（页间 `---` 分隔）+ `result.json`（扁平化 `full_content_list`，含 `id/page_idx/type/text/bbox/score/order` 支持双向定位）。

### Apple Silicon MLX 模式

类 [`PaddleOCRVLMLXEngine`](../backend/paddleocr_vl_mlx/engine.py#L26) 复用 vLLM 版的流式解析、降级重试与输出归一化，只把识别后端切到 `vl_rec_backend="mlx-vlm-server"`。

- **依赖隔离**：`mlx-vlm>=0.4.2` 依赖 `transformers>=5.1`，与 MinerU 3.2.3 的 `transformers<5.0` 冲突，必须装在独立 `backend/.venv-mlx`，主 `.venv` 只跑 API/Worker/PaddleX。
- **启动方式**：`python backend/start_all.py --accelerator cpu --auto-start-mlx-server` 会用 `backend/.venv-mlx/bin/python -m mlx_vlm.server` 拉起 OpenAI-compatible server，默认 URL 为 `http://127.0.0.1:8111/v1`。
- **模型路径**：默认使用 `backend/model/paddlex_cache/official_models/PaddleOCR-VL-1.6-0.9B`，可用 `--paddleocr-vl-mlx-model-path` 或 `MLX_VLM_API_MODEL_NAME` 覆盖。mlx-vlm 的 `/v1/models` 可能同时展示 Hugging Face 缓存中的其它模型，实际调用由 `vl_rec_api_model_name` 指定。
- **选项差异**：mlx-vlm server 当前不支持 `minPixels/maxPixels`（含 snake_case），MLX 引擎会在调用前过滤这些参数，避免 PaddleOCRVL 抛 warning。
- **前端定位**：PaddleOCR-VL 原始页 JSON 的字段是 `block_content` / `block_label` / `block_bbox`；前端双向定位已按这些字段取文，并过滤 `block_label="number"` 的页码块。

## 3. PaddleOCR-VL 引擎（vLLM 模式）

类 [`PaddleOCRVLVLLMEngine`](../backend/paddleocr_vl_vllm/engine.py#L32)（单例），`parse()` 在 [engine.py:154](../backend/paddleocr_vl_vllm/engine.py#L154)。

- **模型**：同 `PaddleOCR-VL-1.6-0.9B`，但 `vl_rec_backend="vllm-server"`：**版面检测在本地 GPU，VL/OCR 识别卸载到远程 vLLM 服务**。
- **vLLM 连接**：`vllm_api_base` 默认取环境变量 `VLLM_API_BASE` 或 `http://vllm-paddleocr:30023/v1`；`_check_vllm_health` 先试 `{base}/health` 再试 `{base}/v1/models`。
- **可靠性设计**：串行流式（`PADDLEX_INFERENCE_PARALLEL_WORKER_NUM=1`）避免压垮 vLLM；每任务重载 pipeline 避免状态污染；流失败时降级重试（关闭 layout/chart/seal）；`finally` 必清理。
- **输出**：与本地版一致，优先用 `pipeline.concatenate_markdown_pages` 合并，否则 `---` 拼接。

## 4. 音频引擎（SenseVoice）

类 [`SenseVoiceEngine`](../backend/audio_engines/sensevoice_engine.py#L30)（单例），`parse()` 在 [engine.py:216](../backend/audio_engines/sensevoice_engine.py#L216)，基于 FunASR `AutoModel`。

**两种模型路径**：

| 场景 | 模型 | 能力 |
|------|------|------|
| 默认 | `iic/SenseVoiceSmall` + `fsmn-vad` | 多语种 ASR（zh/en/ja/ko/yue）+ 情感识别，无时间戳 |
| 开启说话人分离 | Paraformer-large + `fsmn-vad` + `ct-punc`（标点）+ CAM++（声纹）| 句级时间戳 + 说话人标签（主要 zh-cn）|

- **输入**：FunASR 自行解码（常见 wav/mp3/flac/m4a），无扩展名白名单。视频引擎会先转 16kHz 单声道 WAV。
- **选项**：`language`（`auto/zh/en/ja/ko/yue`）、`use_itn`（逆文本归一化，默认 True）、`enable_speaker_diarization`（→ Paraformer 路径）。
- **输出**：标准 JSON `{format:"audio", transcript, segments:[{start,end,text,speaker,language,emotion}], metadata:{duration,...}}`，并生成带元数据头与时间戳的 Markdown。分离失败自动回退基础模式。

## 5. 视频引擎

类 [`VideoProcessingEngine`](../backend/video_engines/video_engine.py#L19)（单例），`parse()` 在 [engine.py:236](../backend/video_engines/video_engine.py#L236)。

**支持格式**：`.mp4 .avi .mkv .mov .flv .webm .m4v .wmv .mpeg .mpg`。

**处理流程**：
1. **抽音频**：FFmpeg → 16kHz 单声道 PCM WAV（`-vn -acodec pcm_s16le -ar 16000 -ac 1`）。
2. **转写**：委托 `SenseVoiceEngine`（全量 ASR + 可选说话人分离/情感）。
3. **关键帧 OCR（可选，`enable_keyframe_ocr=true`）**：[keyframe_extractor.py](../backend/video_engines/keyframe_extractor.py) 流水线——
   场景检测（OpenCV 帧差，回退固定 10s 间隔）→ 抽帧 → 质量过滤（拉普拉斯清晰度 + 亮度）→ 感知哈希去重（`imagehash.phash`）→ 用 **PaddleOCR-VL 本地引擎** OCR 每帧 → 文本去重（`difflib` 相似度 ≥0.9 丢弃）。
- **选项**：`language`、`use_itn`、`keep_audio`、`enable_keyframe_ocr`、`ocr_backend`（默认 `paddleocr-vl`）、`keep_keyframes`。
- **输出**：音频结果 + 关键帧 OCR 合并到 `content.md`/`content.json`，JSON 标 `type:"video"`，关键帧另存 `<stem>_keyframes.md/.json`。

## 6. 去水印预处理（YOLO + LaMa）

PDF + `remove_watermark=true` 时在解析前执行，[remove_watermark/](../backend/remove_watermark/)：

- **图片去水印** [`WatermarkRemover`](../backend/remove_watermark/watermark_remover.py#L29)：YOLO11x 检测水印框（默认模型 `corzent/yolo11x_watermark_detection`）→ 膨胀生成掩码 → **LaMa** 修复（`simple_lama_inpainting`，回退 OpenCV TELEA）。无检测框则原样复制。
  - 选项：`conf_threshold`（0.35）、`dilation`（10）、`use_lama`（True）、`device`。
- **PDF 去水印** [`PDFWatermarkHandler`](../backend/remove_watermark/pdf_watermark_handler.py#L18)：用 PyMuPDF 自动判别 PDF 类型——
  - **可编辑 PDF**：删注释、关键词文字盖白块（选项 `remove_text/remove_images/remove_annotations/keywords`）。
  - **扫描 PDF**：按 `dpi`（默认 200）渲染成图 → 逐页 YOLO+LaMa → 重组 PDF。

> 仅在 `accelerator=cuda` 时初始化水印引擎（[litserve_worker.py:333](../backend/litserve_worker.py#L333)）。

## 8. `auto` 模式与兜底链

`backend=auto` 时按扩展名分派（[litserve_worker.py:462](../backend/litserve_worker.py#L462)）：

```
格式引擎支持(FASTA/GenBank)?  → 格式引擎
.wav/.mp3/.flac/.m4a/.ogg     → SenseVoice
.mp4/.avi/.mkv/.mov           → 视频引擎
.pdf/.png/.jpg/.jpeg/.docx    → MinerU pipeline
.doc/.xls/.ppt（旧 Office）   → LibreOffice 转新格式后：
                                  .doc→.docx→MinerU 原生
                                  .xls→.xlsx→MarkItDown
                                  .ppt→.pptx→MarkItDown
其它                          → MarkItDown 兜底
```

**Office 处理两条路**：
- `convert_office_to_pdf=true`：`.docx/.xlsx/.pptx/.doc/.xls/.ppt` 先用 LibreOffice 转 PDF 再走 MinerU（[litserve_worker.py:779](../backend/litserve_worker.py#L779)）。
- 否则旧格式 `_convert_office_to_new_format` 转 OOXML（[litserve_worker.py:802](../backend/litserve_worker.py#L802)）。

**MarkItDown**：处理 `.docx` 时额外用 `extract_images_from_docx` 抽图并追加到 Markdown（[litserve_worker.py:723](../backend/litserve_worker.py#L723)）。

## 9. 输出归一化

所有引擎产物经 [`normalize_output()`](../backend/output_normalizer/__init__.py#L32) 统一为：

```
<output_dir>/<文件名>/
  ├── result.md       # 标准 Markdown
  ├── result.json     # 结构化数据（含 bbox/page_idx，支持双向定位）
  └── images/         # 抽取的图片
```

- **归一化器选择**（[__init__.py:32](../backend/output_normalizer/__init__.py#L32)）：检测到 `page_*` 目录 → `PaddleOCROutputNormalizer`，否则 `StandardOutputNormalizer`。
- **`StandardOutputNormalizer`**（[standard_output_normalizer.py](../backend/output_normalizer/standard_output_normalizer.py)）：挑最大 `.md` 改名 `result.md`，合并 `imgs/img/pictures` 等目录到 `images/`，挑 `content_list`/`result` JSON 为 `result.json`，重写 MD 图片引用。
- **`PaddleOCROutputNormalizer`**（[paddleocr_output_normalizer.py](../backend/output_normalizer/paddleocr_output_normalizer.py)）：逐页 `page_*/imgs/` 全局顺序重命名（`image_001.jpg…`）避免冲突，合并各页 `*_res.json`，从 bbox 重建图片名注入 `img_path`。
- **对象存储**（[base_output_normalizer.py:91](../backend/output_normalizer/base_output_normalizer.py#L91)）：若 `MINIO_ENABLED=true` 且有图片，**仅把抽取的图片上传 MinIO**，把 MD/JSON 中的图片链接改写为公网 URL；源文件与 MD/JSON 文本仍留在本地磁盘。上传失败不致命，回退本地路径。

## 10. 「源文档预览」与「双向定位」能力矩阵

任务详情页（[`TaskDetail.vue`](../frontend/src/views/TaskDetail.vue)）有三种结果视图：**完整文档**（Markdown，所有格式都有）、**源文档预览**（左侧 PDF）、**双向定位**（左侧 PDF + 右侧块，点击互相高亮）。后两者能否出现，取决于引擎是否产出了对应产物，而非"文档格式"本身。

### 触发条件（充要）

- **源文档预览**：`task.data.pdf_path` 非空，即输出目录里存在 PDF。仅两种情况成立（[`_ensure_pdf_in_output()`](../backend/litserve_worker.py#L547)）：
  1. 引擎产出 `*_layout.pdf`（MinerU / PaddleOCR-VL 把版面框画在渲染页上）；
  2. 源文件本身是 PDF（无 layout pdf 时直接复制源 PDF 到输出目录）。
- **双向定位**：`json_content` 的块带 `bbox`，且有 PDF 可叠加点击。只有 MinerU 与 PaddleOCR-VL 系列产出这种带坐标的 `content_list`。

> 即：预览只要"有 PDF"，双向定位还需额外"有 bbox JSON"。`pdf_path` / `json_content` 均在 worker 完成时写入任务 `data`（[litserve_worker.py:520](../backend/litserve_worker.py#L520)）。

### 各引擎产物

| 引擎 | `pdf_path`（预览） | 带 bbox 的 `json_content`（双向定位） |
|------|:--:|:--:|
| MinerU `pipeline` / `vlm-*` / `hybrid-*` | ✓ | ✓ |
| PaddleOCR-VL / `paddleocr-vl-vllm` | ✓ | ✓ |
| MarkItDown（兜底） | 仅当源文件是 PDF | ✗（不产出 `json_content`） |
| SenseVoice（音频） | ✗ | ✗ |
| 视频引擎 | ✗ | ✗ |
| 格式引擎（FASTA / GenBank） | ✗ | ✗（有 `json_content` 但**无 bbox**，序列文件无版面坐标） |

### 按输入文件格式

| 输入格式 | 预览 | 双向定位 | 说明 |
|------|:--:|:--:|------|
| **PDF** | ✓ | ✓ | 走 MinerU / PaddleOCR-VL；若被 MarkItDown 处理则仅预览、无定位 |
| **图片** png/jpg/jpeg | ✓ | ✓ | MinerU 把图片当作一页渲染，产出 `_layout.pdf` + bbox |
| **Word** .docx / .doc | ✓ | ✓ | `auto` 模式直接走 MinerU（[litserve_worker.py:472](../backend/litserve_worker.py#L472)）；.doc 先转 .docx |
| **Excel / PPT** .xlsx/.pptx/.xls/.ppt | 取决于 | 取决于 | 勾选 `convert_office_to_pdf` → 转 PDF 走 MinerU → 预览 + 定位都有；否则走 MarkItDown → 仅 Markdown |
| **音频** wav/mp3/flac/m4a/ogg | ✗ | ✗ | 仅转写文本 |
| **视频** mp4/avi/mkv/mov | ✗ | ✗ | 仅分析文本 |
| **生信** FASTA / GenBank | ✗ | ✗ | 仅 Markdown + JSON，无版面 |
| **其它**（html/csv/txt/epub 等经 MarkItDown） | ✗ | ✗ | 纯文本转换 |

**一句话**：预览 + 双向定位 = **PDF、图片、Word**（以及显式转 PDF 的 Office），因为只有 MinerU / PaddleOCR-VL 才同时产出 `_layout.pdf` 和带 `bbox` 的 JSON；音视频、生信、以及 MarkItDown 兜底的格式只有"完整文档"（Markdown）视图。

> 双向定位的 bbox 坐标约定与渲染、各块字段结构，见 [04 · 本地开发环境与解析问题修复](./04-本地开发环境与解析问题修复.md) 的问题 5/6 与附录。
